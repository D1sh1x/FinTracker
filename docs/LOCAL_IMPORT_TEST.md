# Локальный тест скриншотов и Qwen3-4B

Подготовлено 14 октября 2026 года. Лаборатория доступна на **http://localhost:8090**. Основное приложение продолжает работать на http://localhost:8088.

## Что подготовлено

- Go-сервер и отдельный интерфейс тестирования: выбор файла или вставка PNG/JPEG через Ctrl+V, OCR, разбор строк и категоризация.
- Qwen3-4B-Instruct-2507 в формате Q4_K_M через официальный llama.cpp runtime `b10884`.
- Tesseract с русским и английским языками, работающий нативно в Docker.
- Режим CPU с 4 потоками и режим NVIDIA GPU.
- Фиксированный тестовый каталог категорий с вариантом **«Не определено»**. Неясные покупки, недостаток данных и непроверяемый ответ модели получают этот вариант. Для технической ошибки дополнительно показывается предупреждение.
- Редактирование описания, направления, суммы и даты; повторная классификация и скачивание результата JSON с измерениями.
- Все операции считаются рублёвыми по настройке владельца. Определение валюты и предупреждения о нераспознанном символе валюты отключены.
- В раскладке истории WB название повторно распознаётся отдельно от иконок и суммы. Банковская категория хранится отдельной подписью; сомнительное название отмечается для проверки.

Это этап проверки извлечения и категорий. Операции в финансовой БД не создаются. Каталог лаборатории пока независим от категорий профилей. Загруженные изображения обрабатываются в памяти и не сохраняются на сервере; изображение и результат видны в текущей странице браузера. Скачивание JSON выполняется по нажатию пользователя.

## Как попробовать

1. Открой http://localhost:8090.
2. Нажми «Контрольный пример», затем «Проверить текст»: это проверяет Qwen отдельно от OCR.
3. Выбери скриншот WB Банка в PNG/JPEG либо скопируй изображение и нажми **Ctrl+V** на странице. На Windows можно сделать снимок области через **Win+Shift+S**, затем вставить его в стенд. Появится предпросмотр. Укажи дату съёмки и нажми «Распознать и классифицировать».
4. Сравни текст OCR, суммы, знаки и даты с изображением. Исправь текст и нажми «Проверить текст», либо исправь конкретную строку и нажми «Переклассифицировать после правок».
5. Если парсер не выделил операцию, добавь её вручную. Для непонятного описания модель должна предложить «Не определено».
6. При желании скачай JSON: в нём останутся строки, пояснения и измерения для сравнения тестов.

Для сравнения разных скриншотов сохраняй одинаковые настройки модели и отдельно оценивай OCR и категоризацию. Время Qwen не включает загрузку весов при запуске контейнера. Ошибочная дата/сумма не исправляется нейросетью автоматически.

Вставленное изображение заменяет выбранный файл; последующий выбор файла заменяет вставленное изображение. Обычный Ctrl+V текста в редакторах работает как обычно. Обрабатывается первое изображение PNG/JPEG до 10 МБ из события вставки; неподдерживаемый формат или слишком большой файл не заменяет текущий скриншот. Во время распознавания замена изображения заблокирована. Байты полученного изображения передаются на сервер без дополнительного преобразования приложением; браузер может переупаковать PNG при работе с системным буфером.

## Запуск и остановка

Из корня проекта в PowerShell 7 (`pwsh`), при запущенном Docker Desktop. Скрипт скачивания использует `Invoke-WebRequest -Resume`, доступный в PowerShell 7:

```powershell
.\scripts\start-import-lab.ps1 -Mode gpu
```

Режим без видеокарты, близкий к будущему серверу:

```powershell
.\scripts\start-import-lab.ps1 -Mode cpu -Threads 4
```

Параметр `-SkipBuild` переключает уже собранный стенд между режимами без повторной сборки:

```powershell
.\scripts\start-import-lab.ps1 -Mode gpu -SkipBuild
```

Остановка только лаборатории:

```powershell
.\scripts\start-import-lab.ps1 -Mode gpu -Stop
```

Оба режима используют проект Compose `fintrack-lab` и одни и те же локальные веса. Основной проект `fintrack` не останавливается и его тома не используются. Повторная загрузка весов при обычном запуске не нужна; скрипт проверяет SHA-256 существующего файла. Изменённые исходники требуют запуска без `-SkipBuild`.

Первый запуск скачивает веса примерно 2,50 ГБ и Docker-образы; CUDA-образ заметно больше CPU-образа. Веса лежат в `.local/models/`, исключённой из Git. Исходная модель — [Qwen/Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507); используемая GGUF-конверсия — [bartowski/Qwen_Qwen3-4B-Instruct-2507-GGUF](https://huggingface.co/bartowski/Qwen_Qwen3-4B-Instruct-2507-GGUF).

Ревизия весов: `ae44f08e1392f39c0e474af10c3ff8355c8b6688`. SHA-256:

```text
2fde00ce69dd4899c70d020845e2638353015bba0fdf161b3eb965f2bca4464e
```

Docker-образы CPU/GPU закреплены digest в Compose. Контекст модели — 4096 токенов, генерация без thinking, temperature 0, один параллельный запрос. Классификация идёт группами до 8 строк; максимум 30 строк на один тест. Описания для модели ограничены первыми 300 символами, поэтому существенное назначение платежа нужно ставить в начале.

Если модель загружается, дождись статуса «Qwen готов к тесту». Ошибка соединения/неполный ответ модели показывает предупреждение и «Не определено», а не успешную уверенную классификацию. Кнопка отмены сохраняет предыдущий результат.

## Измерение на этом компьютере

Обнаружены Intel Core i7-8700 (12 логических потоков) и NVIDIA GeForce RTX 5060 с 8 ГБ VRAM. Docker видит 12 CPU и примерно 35,2 ГиБ RAM. Измерялся один и тот же синтетический набор из 6 текстовых операций, без OCR:

| Режим | Время категоризации | Скорость генерации |
| --- | --- | --- |
| CPU, 4 потока | 52,7 с | 7,3 токена/с |
| NVIDIA RTX 5060 | 2,79 с | 92,3 токена/с |

Продукты, кафе, аренда и зарплата получили ожидаемые категории. Wildberries без названия товара и перевод СБП без назначения получили «Не определено». CPU-контейнер после прогрева занимал примерно 2,4 ГиБ RAM; это наблюдение в простое, не измеренный максимум.

Это контроль производительности и работоспособности на шести примерах, а не оценка точности на реальной банковской выборке. Характеристики будущего сервера могут отличаться. Для собственного измерения показываются общее время, OCR, Qwen и скорость генерации; JSON содержит число входных и выходных токенов. Скорость токенов относится к генерации ответа, а время Qwen включает также обработку prompt.

## Проверки

- 33 Go-сценария, включая подслучаи: точные копейки, даты, отсутствие направления, несколько сумм, ограничения, ошибки модели, неправильная категория, отсутствующий index, отмена, блокировка параллельного теста, разбор WB без ложных операций из реквизитов/кешбэка и независимое уточнение названий без изменения денежных полей.
- Отдельно проверены ручные исправления, очистка устаревших замечаний к полям, UUID ручной строки и некорректные суммы/даты.
- `go vet` и Linux race detector прошли. Postman Smoke на настоящем runtime: 4 запроса, 8 assertions, 0 ошибок; lint коллекции и синтаксическая проверка OpenAPI прошли.
- Браузерный сценарий использует настоящий Ctrl+V синтетического PNG и реальные OCR/Qwen: 3 операции, неизвестный маркетплейс, исправление описания, ручная строка, JSON-выгрузка, отмена, тёмная тема и ширины 360/390/1280.
- Отдельный сценарий вставки проверяет настоящий Ctrl+V PNG/текста, JPEG через событие вставки, замену файла, ошибки формата/размера, блокировку во время теста, сохранение пикселей при браузерной вставке и неизменность переданных приложением байтов. Обработка API в этой проверке подменена: она проверяет доставку изображения и интерфейс; реальное распознавание проверяет предыдущий сценарий.
- Проверен один реальный скриншот WB Банка: 8 полностью видимых операций, все числовые суммы и направления совпали после исправлений. Подробности и ограничения — в [WB_SCREENSHOT_CHECK.md](WB_SCREENSHOT_CHECK.md). Геометрический парсер экспериментальный; другие раскладки могут требовать исправления текста или ручного добавления строки.
- Растровый ввод ограничен 10 МБ и 20 млн пикселей; поддерживаются PNG/JPEG. Неполные строки и нераспознанный знак показываются для проверки.
- Валюта фиксирована RUB, даже если OCR не распознал или исказил знак ₽. Остатки P/Р после суммы не входят в название. Мультивалютные операции и конвертация не поддерживаются.

Синтетические результаты/скриншоты/логи находятся в игнорируемых `.local/lab-*`. Финансовая база и основной API в этих испытаниях не изменялись.

## Повторение проверок

API-контракт: `api/import-lab.openapi.json`, также доступен по http://localhost:8090/openapi.json. Отдельная локальная Postman-коллекция: `postman/collections/FinTrack Import Lab`.

В ответе `rows.description` содержит название, `rows.bank_category` — опциональную подпись банка. Исходный текст `text` и `lines.text` сохраняется для проверки; опциональные `lines.name` / `name_confidence` содержат уточнение названия отдельным проходом. Повторная проверка сырого текста не выполняет этот проход: для сохранения уточнённых названий используй редактор строк и «Переклассифицировать после правок».

```powershell
cd backend
go test ./internal/importlab ./cmd/importlab
go vet ./internal/importlab ./cmd/importlab
```

Из корня проекта при работающем стенде:

```powershell
.\frontend\node_modules\.bin\postman.cmd collection run 'postman/collections/FinTrack Import Lab' -i Smoke --no-report-events
node scripts/check-import-lab.mjs
node scripts/check-lab-clipboard.mjs
```

Playwright требует установленных Chromium-бинарников. При нестандартном расположении укажи `PLAYWRIGHT_BROWSERS_PATH` перед запуском. Go-тесты используют локальный тестовый HTTP-сервер модели, поэтому не требуют весов или PostgreSQL. Браузерный сценарий и Postman Smoke проверяют настоящий запущенный runtime.

Перегенерация коллекции:

```powershell
.\frontend\node_modules\.bin\postman.cmd spec generate collection api/import-lab.openapi.json -n 'FinTrack Import Lab' --folder-strategy Tags --force
node scripts/build-lab-smoke.mjs
```

Следующий эксперимент — независимые обезличенные скриншоты WB, разные дни/темы и сравнение точности полей. После этого можно сравнить Tesseract с PP-OCRv5 и решать, достаточно ли текущего OCR для поддерживаемого экрана.
