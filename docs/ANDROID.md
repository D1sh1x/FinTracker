# Android APK

Android-приложение использует тот же React-интерфейс с лавандовой палитрой и тот же Go API, что и сайт. Capacitor 8 упаковывает интерфейс внутрь APK; данные хранятся на сервере. Минимальная версия — Android 8.0 (API 26), target SDK — 36. Нужен актуальный Android System WebView. Автономный учёт без сервера пока не реализован.

## Установка и подключение

Готовая подписанная сборка: `artifacts/android/FinTrack-0.1.0-alpha.apk`. Скопируйте APK на телефон, откройте и разрешите установку для приложения, через которое открыли файл. Это персональная alpha-сборка вне Google Play.

При первом запуске заполните общий вход:

- Адрес: **https://167.86.68.233:9443** (уже подставлен).
- Логин: `owner`.
- Пароль: из локального файла `.local/vps-access.txt` на ПК.

Затем выберите существующий профиль или создайте новый. Сайт и APK используют одну серверную базу: записи не требуется переносить между устройствами. Для подключения достаточно интернета, домен/VPN/USB/работающий ПК не нужны. В браузере телефона можно открыть тот же HTTPS-адрес. Подключение APK на физическом телефоне ещё предстоит проверить: внешний TLS в тестовом эмуляторе завершается ошибкой также на сторонних сайтах. Проверка сертификатов в приложении остаётся включённой.

Адрес и пароль меняются в «Настройки → Подключение к серверу». Подключение проверяется до сохранения. Пароль хранится в приватных настройках Android в зашифрованном виде; ключ AES/GCM — в Android Keystore, в APK пароль не зашит. Копирование настроек через Android backup отключено. При смене сервера очищаются кэш запросов и выбор профиля, открывается обзор.

## Сохранённые функции

Профили, доходы и расходы, категории, история, общий бюджет и лимиты категорий, остатки и перерасход, капитал/счета/переводы/ручная переоценка, импорт скриншотов с подтверждением и CSV используют общий код сайта и существующий контракт API.

Android-адаптация добавляет:

- системные отступы, работу с клавиатурой и кнопку «Назад»;
- выбор PNG/JPEG и кнопку «Вставить из буфера» для изображения, если Android предоставляет доступ к его URI;
- системный выбор места сохранения CSV без широкого доступа к накопителю;
- светлую/тёмную/системную тему, включая системные панели;
- общий вход к VPS через native HTTP, включая multipart-изображения и точные денежные строки.

Обычные вызовы API ограничены 20 секундами, подключение — 10 секундами, экспорт — 60 секундами. Отмена JS-запроса прекращает ожидание; уже отправленный native HTTP может завершиться на сервере и ограничивается native timeout. Существующие UUID, версии и подтверждения импорта позволяют безопасно повторять финансовые запросы.

На VPS **Qwen пока не запущен**: OCR есть, классификация моделью недоступна, неизвестные категории остаются «Не определено». Сборка APK не добавляет чтение банковских push-уведомлений и работу в фоне — это следующий этап.

## Сборка на Windows

Нужны Node.js с зависимостями `frontend`, JDK 21, Android SDK Platform 36 и Build Tools 36.0.0. Android Studio необязательна для командной сборки. В подготовленном окружении JDK/SDK лежат в игнорируемом `.local/android/`; SDK содержит также Build Tools 35.0.0, требуемые текущим Android Gradle Plugin.

```powershell
cd frontend
npm ci
cd ..
.\scripts\build-android.ps1 -Verify
```

Для установленного отдельно SDK/JDK можно передать `-JavaHome` и `-SdkRoot` или задать `JAVA_HOME`/`ANDROID_HOME`. Скрипт создаёт временную букву диска для Windows-инструментов, которым мешает кириллица в пути, и убирает её после сборки. `-Offline` подходит после первой успешной загрузки зависимостей.

Результат release: APK и SHA-256 в `artifacts/android/`. `-Configuration Debug` создаёт отдельный файл с суффиксом `-debug.apk`, не заменяя release.

Первый release-запуск создаёт ключ `.local/android/signing/fintrack-release.jks` и пароль `.local/android/signing/password.txt`. **Сохраните оба файла отдельно от Git**: они нужны для обновления установленного приложения тем же сертификатом. Не меняйте ключ между версиями. Для обновления увеличивайте VersionCode:

```powershell
.\scripts\build-android.ps1 -VersionCode 2 -VersionName 0.1.1-alpha -Verify
```

## Проверки

`npm test` в `frontend` проверяет денежные форматы, Android URL/авторизацию, сохранение точности, статусы ошибок, multipart, отмену и CSV. Сборка с `-Verify` запускает Android lint и доступные unit-test задачи; Java unit-тестов приложения пока нет, задачи `NO-SOURCE` не считаются покрытием поведения.

Два Android-сценария предназначены **только для эмулятора** и отдельной тестовой БД/API на `127.0.0.1:18091`; не направляйте их на рабочие финансы:

```powershell
frontend\node_modules\.bin\postman.cmd simulation run postman/simulations/android-connection.sim.yaml --port 4900 --output ndjson --no-history
# В другом терминале после запуска debug APK и отдельного API:
node scripts/check-android.mjs
node scripts/check-android-files.mjs
```

Эмулятору нужны `adb reverse tcp:4900 tcp:4900` и `adb reverse tcp:18091 tcp:18091`. Сценарий финансов проверяет native HTTP против Postman-симуляции общего входа, затем настоящий Go API. Он создаёт тестовые записи; файловый сценарий использует созданный тестовый профиль. Подробные результаты и оставшиеся ограничения записываются в `VERIFICATION.md`.

При необходимости теста через USB сохранён `scripts/connect-android-usb.ps1`: он соединяет телефон с SSH-туннелем ПК. Для обычного доступа по HTTPS этот режим не нужен.
