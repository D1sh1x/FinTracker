# Импорт банковских скриншотов

Импорт встроен в основной сайт: **http://localhost:8088/#imports**, пункт «Из скриншота». Сервер и фоновая обработка написаны на Go. Tesseract `rus+eng` выделяет текст; Qwen3-4B-Instruct-2507 Q4_K_M предлагает только категории из выбранного профиля. Суммы разбираются отдельно как целые копейки, модель их не меняет. Валюта всегда RUB.

## Использование

1. Выберите профиль и откройте «Из скриншота».
2. Выберите PNG/JPEG либо скопируйте изображение и нажмите Ctrl+V на странице. Ограничения: один файл, 10 МиБ, 20 млн пикселей. Обычная вставка текста в поля остаётся доступна.
3. Укажите **дату съёмки**, чтобы «Сегодня» и «Вчера» получили правильные даты. Дата загрузки не подставляется автоматически.
4. Нажмите «Распознать скриншот». Можно закрыть страницу: задача и результат сохраняются в БД; открыть их можно через «Последние импорты» текущего профиля.
5. Сверьте названия, суммы, даты, направления и категории. Можно исправлять и сохранять черновик, добавлять строки вручную и исключать ненужные. Даты должны попадать между началом учёта кошелька и сегодняшним днём.
6. Отметьте проверку и подтвердите. **Только выбранные строки** станут операциями; остальные пропускаются, импорт закрывается. Баланс, общий бюджет и лимиты категорий пересчитываются обычными правилами приложения.

Если назначение неизвестно или модель недоступна, строка получает «Не определено». Это отдельные категории доходов и расходов. Переводы человеку/СБП без назначения и общие цифровые подписки требуют ручного выбора категории. Переводы между своими счетами следует пропустить: отдельного учёта переводов в MVP нет. Категории «Не определено» можно редактировать/архивировать как остальные; если такая категория больше не активна, перед сохранением понадобится выбрать активную категорию.

## Запуск на этом компьютере

Основной сайт использует уже подготовленную модель лаборатории через `host.docker.internal:8091`, без второго экземпляра весов:

```powershell
.\scripts\start-import-lab.ps1 -Mode gpu -SkipBuild
.\scripts\compose.ps1
```

Для CPU замените `gpu` на `cpu`. После завершения Docker-сборки Go и Node.js на машине запуска не нужны. Tesseract и языковые данные входят в образ API. При запуске Go напрямую вне Docker нужно установить Tesseract и `rus+eng`, доступные через PATH.

Можно указать другой совместимый сервер модели через `QWEN_URL` в `.env`. При недоступной модели OCR продолжает работать, а категории остаются неопределёнными с предупреждением.

## Отдельный запуск модели на своём сервере

Скачайте проверенные веса в `.local/models/` командой `scripts/download-lab-model.ps1` на Windows и перенесите их на сервер. Имя, SHA-256 и лицензия описаны в [LOCAL_IMPORT_TEST.md](LOCAL_IMPORT_TEST.md). CPU-вариант для сервера 6 ядер / 16 ГБ RAM:

```sh
docker compose -f compose.yml -f compose.imports.yml up -d --build --wait
```

Модель не публикует внешний порт, API обращается к `http://qwen:8080`. Контейнер модели ограничен 8 ГБ RAM и использует четыре CPU-потока. Дождитесь healthy у `qwen` перед первым импортом. В GPU-варианте добавьте `-f compose.imports.gpu.yml`; нужна NVIDIA GPU с поддержкой Docker. Основной сайт запускается и без модели, но для автоматических категорий требуется её готовность. Без `compose.imports.yml` адрес `host.docker.internal` рассчитан на Docker Desktop; на Linux задайте доступный API адрес модели явно.

CPU заметно медленнее: лабораторный прогон шести текстовых операций занял 52,7 с на i7-8700; результат другого сервера нужно измерить. Задача обрабатывается до пяти минут; запрос загрузки возвращает 202 быстро, сайт опрашивает статус. В одном API работает один обработчик; аренда задачи в БД длится шесть минут. После аварийного завершения просроченная задача забирается заново. При штатной остановке она возвращается в очередь. Необработанная задача старше семи дней становится failed; повторная загрузка обновляет срок ожидания.

## Повторы и дубли

- SHA-256 байтов файла уникален в пределах профиля. Повтор того же файла возвращает текущий или подтверждённый импорт; failed/cancelled можно запустить повторно. Перекодированное изображение имеет другой SHA-256.
- Для готового черновика показываются до пяти существующих активных операций с одинаковыми датой, направлением и суммой. Это **кандидаты**, а не доказательство дубля. Для сохранения такой строки нужно явно отметить «Это отдельная операция». Сервер перепроверяет совпадения перед записью.
- Одинаковые суммы внутри одного скриншота автоматически не исключаются. Несколько одинаковых реальных покупок допустимы — сверяйте строки вручную.
- Подтверждение атомарно: ошибка любой выбранной строки откатывает все финансовые записи этого запроса. Версия защищает от устаревших правок.
- Повтор точно такого же подтверждения возвращает первоначальную квитанцию. Другая версия/набор/порядок выбранных строк возвращает 409. При потере ответа интерфейс сохраняет запрос и предлагает его повторить.
- Удаление операции в истории не позволяет тому же импорту незаметно создать её заново. Квитанция показывает первоначальный результат даже после последующих правок/удалений операций.

## Данные

Оригинальное изображение хранится в `screenshot_imports.image` только для queued/processing, затем очищается при успехе, ошибке или отмене. Снимок может попасть в резервную копию БД, сделанную во время обработки. Очистка текущей БД не удаляет ранее созданные backup-файлы.

Черновик хранит OCR-текст, координаты/оценки текста, распознанные и исправленные строки, причины категорий, SHA-256 и квитанцию. Автоматического удаления истории нет. После перезагрузки страницы локальный предпросмотр пропадает: вставьте оригинал повторно для визуальной сверки. Несохранённые правки полей хранятся только в текущей вкладке — используйте «Сохранить правки» до перехода на другой раздел/профиль. Финансовые операции содержат обычные поля и `source: screenshot`; банковское изображение не копируется в таблицу операций.

## Контракт и проверки

Контракт: [../api/openapi.json](../api/openapi.json), шесть методов `GET/POST /profiles/{p}/imports`, `GET /{id}`, `PATCH /{id}/rows`, `POST /{id}/confirm`, `POST /{id}/cancel`. Postman: папки `Screenshot imports` и `Import smoke` в основной коллекции. `scripts/build-main-import-postman.mjs` обновляет сохранённые запросы по существующему OpenAPI. Ничего не публикуется в облачный workspace.

Сквозной браузерный прогон **создаёт финансовые записи** и предназначен только для отдельной `fintrack_e2e_test`: Docker API на 8002, Vite на 5175 с `VITE_API_TARGET=http://127.0.0.1:8002`. После проверки этих настроек:

```powershell
$env:FINTRACK_IMPORT_TEST_ALLOWED='1'
node scripts/check-main-import.mjs 'полный-путь-к-WB-скриншоту.png'
```

Частный скриншот и результаты находятся вне Git. Дата `2026-10-14` в этом прогоне — тестовое предположение, а не подтверждённая дата исходного изображения.

Проверено на предоставленном WB-скриншоте: 8 полностью видимых операций, 8/8 сумм и читаемых названий, пять категорий профиля и три «Не определено». Расходы 263 157 коп., доходы 60 000 коп. Проверены настоящий Ctrl+V изображения/текста, сохранение/повторное открытие правок, повтор после потери ответа подтверждения, SHA-дедупликация и точный перерасход категории. Это проверка одного образца, не оценка качества на других банках.

Также прошли Go/PostgreSQL-тесты, `go vet`, Linux race detector, 11 тестов денежного ввода, восемь существующих браузерных сценариев, Postman финансовый Smoke (22 запроса / 35 assertions) и Import smoke (7 запросов / 14 assertions). Lint основной коллекции: 59 запросов без ошибок/предупреждений; синтаксический lint OpenAPI успешен. Новые серверные тесты подменяют OCR/модель для детерминированной проверки отмены, восстановления, изоляции профилей, дублей, версий и конкурентного подтверждения; настоящая модель проверена отдельно сквозным прогоном.
