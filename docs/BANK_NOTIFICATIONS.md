# Покупки из уведомлений WB Банка

Функция доступна в Android APK **0.2.0-alpha**. Сайт на ПК и APK видят одну серверную базу: выберите одинаковый профиль. На VPS установлен Go API со схемой `0006`; сайт доступен на **https://167.86.68.233:9443**. Постоянно включённый ПК не нужен.

## Как включить

1. Установите `artifacts/android/FinTrack-0.2.0-alpha.apk` поверх предыдущей release APK. Подключение и данные сохраняются; удалять приложение перед обновлением не нужно.
2. Войдите на сервер и выберите свой профиль.
3. Откройте **Настройки → Покупки из WB Банка → Разрешить доступ к уведомлениям**. Разрешите доступ ФинТреку в системных настройках Android и вернитесь в приложение. При установке APK вручную Android может потребовать разрешить «Ограниченные настройки» в карточке ФинТрека.
4. Выберите счёт, соответствующий вашей единственной карте, и нажмите **«Включить для этого профиля»**.
5. После следующей покупки проверьте историю и журнал в этом же разделе. Кнопка **«Отправить сейчас»** запрашивает фоновую отправку; Android определяет время запуска задания.

В строке «Включено» показаны закреплённые профиль и счёт. Просмотр другого профиля не меняет привязку. Уже сохранённые пуши относятся к исходному профилю/счёту. Кнопка «Выключить» останавливает новые импорты и повторы. Уже отправленный запрос может успеть завершиться на сервере.

## Что распознаётся

Читается только пакет **`ru.wildberries.bank`** — [приложение разработчика WB Банка в RuStore](https://www.rustore.ru/catalog/app/ru.wildberries.bank). Mir Pay, другие банки и остальные приложения игнорируются. Android выдаёт системный доступ к уведомлениям, а фильтр приложения отбрасывает чужие пакеты до чтения текста и записи в очередь. Пустой текст WB Банка вызывает предупреждение.

Текущий формат — покупки в рублях:

```text
Покупка 43 ₽ по карте *7055 Транспорт Краснодара.
Доступно 933,48 ₽
```

Получится расход **43,00 ₽**, описание «Транспорт Краснодара», категория «Транспорт». Остаток **933,48 ₽** не считается расходом и не заменяет баланс счёта. Суммы разбираются в целых копейках без float. Дата берётся из времени уведомления с учётом часового пояса профиля.

Сначала применяются узкие правила для известных названий транспорта/продуктовых магазинов. Для остальных описаний API пробует существующий классификатор Qwen с ограничением ожидания 6 секунд. Неизвестный ответ или недоступная модель дают **«Не определено»**. На текущем VPS Qwen не запущен, поэтому неизвестные магазины попадают туда. Категорию можно исправить в истории. Если сервер отклоняет счёт или выбранную категорию, запись остаётся для ручной проверки.

Переводы СБП, доходы, возвраты, отмены и иные форматы пока не импортируются. Старые уведомления при включении не перечитываются. Непонятная сумма покупки не угадывается: запись получает статус «Проверьте вручную» без финансовой операции.

## Очередь и повторы

Покупки сохраняются в приватной SQLite на телефоне до отправки. Закрытие приложения или перезапуск процесса не удаляет очередь. При отсутствии связи, HTTP 401/403, 408/429 или 5xx запись остаётся ожидающей. Повторы выполняет Android JobScheduler: есть сетевое задание и периодическая проверка примерно раз в 15 минут; энергосбережение может увеличить задержку. После принудительной остановки приложения может потребоваться открыть его снова. Настройка фоновой работы зависит от производителя телефона.

UUID события сохраняется до отправки. API атомарно создаёт расход и квитанцию, поэтому потеря ответа и повтор запроса не создают второй расход. Редактирование или удаление операции не отменяет квитанцию и не восстанавливает удалённый расход при повторе. Другой текст/счёт с тем же UUID отклоняется. Две разные покупки с одинаковой суммой сохраняются отдельно.

На телефоне повторы различаются по ключу и времени Android-уведомления; при отсутствии времени также учитывается активное уведомление. Если банк переиздаст покупку как совершенно новое уведомление, возможен дубль. Изменение текста с тем же ключом и временем не заменяет сохранённую покупку. Реальное поведение WB Банка на физическом телефоне ещё предстоит подтвердить.

Ручной ввод или импорт скриншота той же покупки могут пересечься с пушем. Не вносите одну покупку двумя способами без сверки истории. Между разными источниками автоимпорт пушей не гарантирует устранение дублей.

Журнал показывает последние 30 записей, счётчики учитывают всю очередь. Исходные тексты хранятся в приватной базе приложения; Android backup отключён. Удаление приложения очищает очередь и журнал, серверные операции остаются. Сервер хранит описание операции и хеш запроса, а не полный пуш. При смене адреса сервера автоимпорт выключается; старые записи не отправляются в другую базу и требуют ручной сверки.

## Проверки для разработчика

Нужны отдельный Go API/БД на `127.0.0.1:18091`, debug APK, подготовленный Android SDK и изолированный эмулятор. Проверки создают тестовые профили и очищают данные ФинТрека на эмуляторе. Не направляйте их на рабочую базу.

```powershell
.\scripts\build-android.ps1 -Configuration Debug -Offline -Verify
.\scripts\android-notification-fixture\build.ps1 -Serial emulator-5556
.local\android\sdk\platform-tools\adb.exe -s emulator-5556 reverse tcp:4901 tcp:4901
frontend\node_modules\.bin\postman.cmd simulation run postman/simulations/wb-notification-sync.sim.yaml --port 4901 --output ndjson --no-history
# В другом терминале:
node scripts/check-bank-notifications.mjs
```

Fixture намеренно использует пакет WB Банка для проверки настоящего `NotificationListenerService`. Скрипт установки запрещает физические устройства. **Не устанавливайте fixture на личный телефон:** там должно оставаться настоящее банковское приложение.

Postman-симуляция проксирует запросы к отдельному Go API и воспроизводит 503, 401 и потерю ответа после записи в БД. Коллекция `Notification smoke` проверяет контракт, повтор, конфликт и отклонение Mir Pay/остатка без покупки. Go-тесты дополнительно проверяют конкурентные повторы и принадлежность счёта профилю. Результаты: [VERIFICATION.md](../VERIFICATION.md).
